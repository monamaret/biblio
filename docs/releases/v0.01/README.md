# biblio-cli — v0.01 User Guide

**Release**: Scaffold and theme a site
**Status**: foundation release — no live deployment (v0.02) and no
agent/terminal-facing capability (v0.03) yet. Everything here is demonstrated
purely through local preview.

`biblio-cli` is a single binary that takes you from "no project" to a
running local preview of a themed, content-indexed site, using three
commands: `new`, `index`, and `dev`.

## Install

**Download a prebuilt binary** (recommended for end users): grab the binary
for your platform from the project's GitHub Releases page and put it on
your `PATH`.

**Or install from source** (requires Go 1.22+):

```sh
go install github.com/monamaret/biblio/cmd/biblio-cli@latest
```

Check it's installed:

```sh
biblio-cli --version
```

### Testing against the local repo (no `go install`)

To try out changes from a checkout of this repo instead of a published
version, build and run straight from source:

```sh
cd /path/to/biblio   # repo root, where go.mod lives

# Build a local binary
go build -o ./bin/biblio-cli ./cmd/biblio-cli
./bin/biblio-cli --version

# Or run without building a binary at all
go run ./cmd/biblio-cli new my-profile-site --type=profile --domain=example.com --theme=profile-default
```

Everything in the rest of this guide works the same way with `go run
./cmd/biblio-cli <args>` in place of `biblio-cli <args>` — just remember
that `new`/`index`/`dev` operate on the current working directory, so `cd`
into the scaffolded project before running `go run` again for `index` or
`dev`:

```sh
cd my-profile-site
go run /path/to/biblio/cmd/biblio-cli index
go run /path/to/biblio/cmd/biblio-cli dev
```

If you built a local binary with `go build` above, put `./bin/` on your
`PATH` (or invoke it by its full/relative path) and use it exactly as
`biblio-cli` is used elsewhere in this guide.

## Concepts

- **Site type** — every project is exactly one of three types, chosen at
  scaffold time: `profile`, `log` (a project log), or `docs` (documentation).
  The type determines the seeded content shape, the required frontmatter
  fields, and which theme presets are available.
- **Theme preset** — a ready-to-use, named set of design tokens (colors,
  fonts) for a given site type. v0.01 ships exactly one preset per type:
  `profile-default`, `log-default`, `docs-default`. Choosing a preset
  generates `tokens.css` for the project.
- **Content index** — `content-index.json`, the single canonical index of
  every authored page/entry (with derived `slug`/`path` and structured
  frontmatter), generated by `biblio-cli index`. This is the shape both the
  rendered site and the future agent-facing layer (v0.03) will read from.
- **Guided flow** — every command works without any flags: if you omit
  `--type`, `--domain`, or `--theme` on `new`, a Bubble Tea terminal UI
  prompts you interactively instead. Flags are the scripting/repeat-use
  path, not the only path.

## Commands

### `biblio-cli new <project-name>`

Scaffolds a complete, runnable, themed site project in a new directory named
`<project-name>`.

```sh
biblio-cli new my-profile-site --type=profile --domain=example.com --theme=profile-default
```

| Flag | Required | Values | If omitted |
|---|---|---|---|
| `--type` | no | `profile` \| `log` \| `docs` | prompted interactively |
| `--domain` | no | a domain string | prompted interactively |
| `--theme` | no | a preset id matching `--type` | prompted interactively, offering only presets valid for the chosen `--type` |

Run with no flags at all to go through the guided flow end to end:

```sh
biblio-cli new my-profile-site
```

**What gets generated**, inside `my-profile-site/`:

- `content/` — seeded with starter Markdown content for the chosen site
  type (e.g. an `about.md` for `profile`, a sample post for `log`, an
  `index.md` for `docs`).
- `content/site.yaml` — the project's declared site type, name,
  description, and `mcp_enabled: true` (the agent-facing on/off setting,
  used starting in v0.03).
- `wrangler.jsonc` — deployment-routing config, pre-filled with the route
  derived from `--domain`.
- `tokens.css` — the generated theme file matching the chosen preset.

**Failure behavior**: an unknown `--type`, a `--theme` that doesn't belong
to the chosen `--type`, or a `project-name` that collides with an existing
directory all produce a clear, actionable error — and never leave a
partially-written project directory behind.

### `biblio-cli index [path]`

Reads every `.md` file under a content directory, validates its
frontmatter, and writes the canonical `content-index.json`.

```sh
cd my-profile-site
biblio-cli index
```

- With no argument, indexes `./content` in the current directory and writes
  `content-index.json` alongside it.
- Pass an explicit path to index a different content directory instead:
  `biblio-cli index path/to/content`.

**Required frontmatter fields by site type**:

| Site type | Required fields |
|---|---|
| `profile` | `title` |
| `log` | `title`, `date` |
| `docs` | `title`, `order` |

**Failure behavior**: if any file has malformed YAML frontmatter, an
unclosed `---` delimiter, or is missing a required field for its site
type, `index` reports **every** failing file (not just the first) and does
not write an incomplete index.

### `biblio-cli dev`

Starts a local preview of the current project: `vite dev` (the site) and
`wrangler dev` (its supporting Worker) together, as one supervised process
pair.

```sh
biblio-cli dev
```

- Surfaces both servers' addresses in the terminal so you can open the site
  in a browser and see your content live, styled per the chosen theme.
- Press `Ctrl+C` to stop both processes cleanly.
- Requires `wrangler.jsonc` to exist in the current directory — if it's
  missing, `dev` fails immediately with a message telling you to run
  `biblio-cli new` first, rather than starting a half-working session.

## End-to-end walkthrough

```sh
# 1. Scaffold a themed project
biblio-cli new my-profile-site --type=profile --domain=example.com --theme=profile-default
cd my-profile-site

# 2. Index the seeded (or your own) content
biblio-cli index
cat content-index.json

# 3. Preview it locally
biblio-cli dev
# open the printed site address in a browser
```

Repeat step 1 with `--type=log` or `--type=docs` to try the other two site
types — each produces its own seeded content, required frontmatter fields,
and matching theme preset.

## Known scope limits in v0.01

- No live deployment — `wrangler.jsonc` is generated but not published.
  Live deployment ships in v0.02.
- No agent/terminal-facing (MCP) capability yet, even though `site.yaml`
  already declares `mcp_enabled: true` in preparation for v0.03.
- Exactly one theme preset per site type — choosing among multiple presets
  for the same type is a future-release concern.
