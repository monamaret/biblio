# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

As of v0.06 (General Availability), `biblio-cli` is a real, working Go module
with a full unit + integration test suite — see `AGENTS.md`'s "Build / Test /
Lint" section for the actual commands (`go build ./...`, `go test ./...`,
`./scripts/check.sh`). `internal/` holds the CLI's packages (`cli`, `scaffold`,
`migrate`, `escalation`, `index`, `content`, `theme`, `devserver`, `tui`);
`templates/site/{profile,log,docs}` holds the three scaffolded site-type
templates (React + Vite + React Router v7 + Cloudflare Worker, each its own
independent npm project). See `docs/releases/v0.06/README.md` for the current
user guide and `docs/releases/CHANGELOG.md` for the full release history.

## Repo layout

- `AGENTS.md` — the canonical project instructions file, auto-loaded by
  opencode (see `opencode.json` -> `instructions`). Filled in since v0.01 and
  kept current through v0.06 (Project, Conventions, Build/Test/Lint,
  Subagents, Skills, Feature development process, Release process, Notes).
  Treat it as the source of truth for project conventions — extend/update it
  alongside this file rather than letting the two drift apart.
- `opencode.json` — opencode config; points `instructions` at `AGENTS.md`.
- `.opencode/agents/` — project-scoped opencode subagent definitions. One
  markdown file per agent; filename = agent name, frontmatter + system-prompt
  body. See `.opencode/agents/README.md` for the exact file format
  (`description` required; optional `model`, `mode`, `permission`, etc.). New
  agents must also be listed under "Subagents" in `AGENTS.md`.
- `.opencode/` also contains opencode's own `package.json`/`node_modules`
  (the `@opencode-ai/plugin` SDK) — this is tooling for building opencode
  plugins/agents, not the project's application dependencies.
- `specs/research/` — research docs for upcoming work, written from
  `research-template.md` (Problem Statement, Background, Libraries & Stack,
  Architecture Patterns, Existing Codebase Evaluation, Security & Compliance,
  Performance/Reliability/Ops, Risks, Open Questions, Decision Log,
  References). Copy this template when starting research on a new feature or
  technical decision and fill in each section before implementation begins.
- `.claude/settings.json` — enabled Claude Code plugins for this repo:
  currently just `mcp-apps`, reflecting this project's actual shape (an
  MCP server / Cloudflare Workers app, generated by `biblio-cli` for each
  scaffolded site). `.claude/skills/speckit-*/` are Spec Kit's generated
  command surface (see `docs/agent-integration-guide.md`), not hand-authored
  plugin config. `.claude/settings.local.json` does not exist in this repo
  and must not be committed — see the policy note below.

### Local vs. project-level agent configuration (issue #199)

Only project-level, shared agent/workflow configuration is tracked here:
`.claude/settings.json`, `.claude/skills/speckit-*/`, `.specify/`,
`opencode.json`, `.opencode/agents/`. Personal or machine-specific
settings — `.claude/settings.local.json`, editor-specific agent config
(`.cursor/`, `.windsurf/`, `.clinerules/`, etc.), or anything else that
varies per developer rather than per project — must never be committed;
`.gitignore` excludes the common cases preventatively. If you find any of
these tracked in git, remove them; if you need a personal override, keep
it untracked locally instead.

## Working in this repo

- Before writing implementation code, check whether `AGENTS.md` has been
  filled in with real conventions/build commands — it is the file opencode
  loads as project instructions and is meant to be the living guide.
- New features or non-trivial technical decisions should start with a
  research doc under `specs/research/`, based on `research-template.md`.
