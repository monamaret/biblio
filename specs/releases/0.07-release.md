# v0.07 — Bug-fix release

**Created**: 2026-06-21
**Status**: Shipped (2026-06-21)
**Roadmap deliverables**: none — unlike v0.01–v0.06, this release wasn't
planned against a [roadmap.md](../research/roadmap.md) item. It's a
reactive bug-fix release closing nine issues filed against v0.06's General
Availability build, found through real use rather than planned work.
**Feature specs**: none — see "Process note" below.
**Depends on**: [v0.06](0.06-release.md) (General Availability)

## Summary

Shortly after v0.06 reached General Availability, real usage of that build
surfaced nine concrete bugs spanning the build pipeline, the local dev
supervisor, the version string, first-run scaffolding, project naming, the
missing release-publishing workflow, and the project's own documentation.
Each was filed as its own GitHub issue, reviewed, fixed on its own branch
with its own test, and merged independently. This release packages that
work as a single, coherent version bump rather than leaving each fix to
trickle out unversioned.

## Bugs fixed

- **#191** — `tokens.css` was written to the project root, which `vite
  build` never copies into its output (only `publicDir` does); production
  builds shipped with no theme CSS. Fixed by writing it to `public/`
  instead.
- **#192** — `biblio-cli dev` killed only the `npx` leader process, not the
  `vite`/`wrangler` child it actually spawns, orphaning it (and sometimes
  hanging the supervisor itself, since `Wait()` blocks on the inherited
  output pipe). Fixed with per-process-group kills.
- **#193** — `biblio-cli -v` always printed `dev`, on both release
  binaries (no `-ldflags` configured) and `go install .../biblio-cli@latest`
  (ldflags don't apply there either way). Fixed both paths.
- **#194** — `biblio-cli dev`'s first run after `new` (or after a fresh
  clone) failed because `wrangler dev` requires its assets directory to
  exist at startup, before any build has run. Fixed by creating it in
  `dev` itself.
- **#195** — A project name containing characters invalid in a Cloudflare
  Workers script name (e.g. a domain-shaped name with dots) broke
  `wrangler.jsonc`. Fixed with a dedicated sanitizer scoped to that one
  field.
- **#196** — No workflow ever existed to actually publish the `goreleaser`
  binaries the README told users to download. Added
  `.github/workflows/release.yml`.
- **#197** — The README didn't explain what this project actually
  scaffolds or how to operate it day to day. Rewritten with clearer scope
  framing and new local-dev/troubleshooting/testing sections.
- **#198** — No documentation existed for how the project's coding-agent
  tooling (Spec Kit, opencode, Claude Code plugin config) fits together.
  Added `docs/agent-integration-guide.md`.
- **#199** — Audited for committed personal/local agent configuration;
  found none, but corrected `CLAUDE.md`'s inaccurate description of
  `.claude/settings.json` and added `.gitignore` guardrails against it
  happening later.

## Verification

Each fix above shipped with its own test demonstrating the bug it closed
(unit tests for #191/#193/#194/#195, a process-tree integration test for
#192 that fails against the pre-fix code and passes against the fix; #196
is exercised end-to-end for the first time by this release's own tag push;
#197/#198/#199 are documentation/config changes verified by manual review
and `git log`/`git ls-files` audits rather than automated tests). See each
issue's linked PR for its specific test plan.

## Process note

Every prior release (v0.01–v0.06) was developed against a planned
[roadmap.md](../research/roadmap.md) deliverable, through the full Spec
Kit cycle (research → feature item → `/speckit.specify` →
`/speckit.plan` → `/speckit.tasks` → `/speckit.implement`), each with its
own nested `specs/releases/0.0X-name/` directory (spec/plan/tasks/
research/data-model/contracts). This release didn't: it's reactive bug
triage against issues filed on the already-shipped v0.06, not a planned
feature, so there is no nested spec/plan/tasks directory here — fabricating
one after the fact would misrepresent how this work actually happened.
This summary, the [CHANGELOG](../../docs/releases/CHANGELOG.md) entry, and
the [v0.07 user guide](../../docs/releases/v0.07/README.md) are this
release's complete record.

## Assumptions

- **Versioning**: this is a bug-fix release with no new commands or
  roadmap deliverables, but it still gets a version bump (0.06 → 0.07)
  rather than a sub-patch number, since the project has no established
  patch-release precedent (v0.01–v0.06 are its only prior tags, and this
  is in fact the very first version this repository has ever tagged in
  git).
